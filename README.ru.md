**PAIR Bridge помогает Codex обращаться к установленным локальным моделям, не выходя из текущей задачи.** Он подключает Codex к маршрутизатору PAIR и явно настроенным устройствам LM Studio или Unsloth Studio, включая компьютеры, доступные через SSH/Tailscale.

| Найти | Спросить и сравнить | Управлять безопасно |
| --- | --- | --- |
| Увидеть доступные устройства, установленные и загруженные модели. | Получить ограниченный ответ или сравнить мнения двух моделей. | Оценить память для нужного контекста, загрузить или выгрузить точный экземпляр. |

Набери `/pair` и выбери навык **pair** или упомяни `$pair`. Astra, Sol и другие модели Codex с поддержкой инструментов смогут использовать эти возможности:

> `/pair найди установленную модель на pc, оцени память для контекста 8192 токенов и попроси проверить эту функцию`

**Сначала установленные модели.** Перед запросом и загрузкой мост проверяет актуальный список: отсутствующая `gpt-oss-20b` будет отмечена как недоступная. Скачивание новых весов требует отдельного явного плана и действия.

Независимый проект сообщества. Не является официальным продуктом OpenAI или NVIDIA.

## Что здесь делает MCP?

**MCP — Model Context Protocol**, протокол, через который Codex узнаёт о доступных инструментах и вызывает их. В нашем плагине небольшой MCP-сервер работает на твоём компьютере и предоставляет инструменты для просмотра, загрузки, выгрузки и опроса моделей.

У каждого участника своя роль:

| Участник | Что делает | Пример |
| --- | --- | --- |
| **Codex** | Разбирается в задаче и использует полученный ответ. | «Нужно второе мнение об этой функции». |
| **MCP-мост** | Предоставляет инструменты поиска, загрузки, выгрузки и запроса. | Проверяет устройство, загружает модель и обращается к ней. |
| **PAIR** | Маршрутизирует запрос, если устройство не задано. | Передаёт вопрос подключённому серверу моделей. |
| **Локальная модель** | Генерирует ответ. | Возвращает замечания по коду. |

**MCP подключает инструменты. PAIR маршрутизирует запросы к моделям.** Основная модель Codex продолжает вести задачу, а локальная модель выступает помощником и возвращает текст для проверки.

На картинке показаны оба маршрута: PAIR может выбрать сервер модели, либо мост обратится напрямую к явно настроенному движку модели.

## Как это выглядит в разговоре

> **Ты:** «Вызови `pair_list`, затем через `pair_ask` попроси модель проверить пограничные случаи этой функции».
>
> **Codex:** Получает актуальный список моделей, выбирает подходящую чат-модель и передаёт ей нужный фрагмент кода через мост.
>
> **Локальная модель:** Возвращает результаты проверки.
>
> **Codex:** Сверяет замечания с кодом и объясняет, какие изменения стоит внести.

Локальная модель получает текст, переданный инструменту. Этот мост не предоставляет ей терминал или прямой доступ к файлам.

## Быстрый старт

### 1 · Подготовь модели

Понадобятся:

- **Codex** с поддержкой каталогов плагинов.
- **[uv](https://docs.astral.sh/uv/getting-started/installation/)**, установленный и доступный через PATH.
- **Запущенный PAIR** хотя бы с одной работающей чат-моделью — для маршрутизируемых запросов.
- **LM Studio 0.4+ или Unsloth Studio** с включённым API на каждом устройстве, которым должен управлять Codex.
- **CLI `lms`** для оценки памяти LM Studio. Для Unsloth Bridge использует API оценки памяти, когда формат модели поддерживается.
- **OpenSSH** и рабочий псевдоним в SSH config для удалённого API движка, доступного только через loopback.

После установки uv перезапусти Codex, чтобы приложение его увидело. Проверить установку можно командой `uv --version`.

### 2 · Установи плагин

Выполни в терминале:

```sh
codex plugin marketplace add GermanMik/pair-bridge
codex plugin add pair-bridge@pair-bridge
```

Команды добавляют наш GitHub-каталог в Codex и устанавливают плагин. Это каталог сообщества, отдельный от общего каталога OpenAI. [Как устроены каталоги плагинов](https://developers.openai.com/plugins/build/plugins).

При первом запуске инструмента uv скачает зафиксированные зависимости и, если потребуется, совместимую версию Python. Следующие запуски используют кэш.

### 3 · Открой новую задачу в Codex

Сначала попробуй навык:

> `/pair покажи мои устройства и доступные модели`

Затем попроси выполнить задачу на конкретном устройстве:

> `/pair загрузи подходящую установленную чат-модель на pc, попроси проверить эту функцию, затем выгрузи запущенный тобой экземпляр`

Если всё настроено, Codex получит ответ модели и сможет использовать его в разговоре. Само наличие модели в списке ещё не означает, что она успешно загрузится.

## Что можно попросить

| Задача | Пример запроса |
| --- | --- |
| Проверить всё | «`/pair покажи настроенные устройства и каталог маршрутизатора PAIR`». |
| Проверить код на устройстве | «`/pair используй pc, чтобы найти ошибки в этом коде`». |
| Получить другой вариант | «`/pair спроси подходящую доступную модель об альтернативе и оцени ответ`». |
| Сравнить устройства | «`/pair спроси одну модель на mac и одну на pc, затем сравни ответы`». |

На разных компьютерах названия моделей различаются. Перед выбором `/pair` проверяет актуальный каталог.

## Как указать адрес PAIR

По умолчанию используется **`http://127.0.0.1:1234/v1`** — адрес прокси PAIR в проверенной конфигурации. Если у тебя другой порт, посмотри адрес в интерфейсе PAIR.

Для изменения адреса создай файл **`.pair-bridge.json` в домашней папке**:

```json
{
  "base_url": "http://127.0.0.1:1234/v1"
}
```

| Система | Расположение файла |
| --- | --- |
| macOS / Linux | `~/.pair-bridge.json` |
| Windows | `%USERPROFILE%\.pair-bridge.json` |

Указывай адрес **маршрутизатора PAIR**. Если указать отдельный сервер движка моделей, будут доступны модели только этого сервера. `127.0.0.1` означает компьютер, на котором запущен мост.

<details>
<summary><strong>Переменные окружения и авторизация</strong></summary>

Можно задать `PAIR_BASE_URL` в окружении, которое наследует Codex. Эта переменная имеет приоритет над файлом настроек.

Если сервер требует bearer-токен, задай `PAIR_API_KEY` в том же окружении. Не вставляй секреты в адрес сервера и не публикуй их в репозитории.

</details>

## Настройка управляемых устройств

Добавь адреса API LM Studio или Unsloth Studio в тот же файл настроек. Они указываются отдельно от прокси PAIR:

```json
{
  "base_url": "http://127.0.0.1:1234/v1",
  "devices": [
    {"id": "mac", "engine": "lmstudio", "base_url": "http://127.0.0.1:1235"},
    {"id": "pc", "engine": "lmstudio", "base_url": "http://127.0.0.1:1235", "ssh_host": "my-pc",
     "auto_unload_models": ["publisher/model-to-release"]},
    {"id": "unsloth", "engine": "unsloth", "base_url": "http://127.0.0.1:8888",
     "api_key_env": "UNSLOTH_API_KEY", "auto_unload_models": ["publisher/model-to-release"]}
  ]
}
```

Укажи адрес API каждого движка; порты выше приведены только для примера. Порт Unsloth Studio по умолчанию — `8888`. `api_key_env` нужен, только если API требует bearer-токен. `ssh_host` должен быть существующим псевдонимом OpenSSH config. Мост создаёт временный туннель только на loopback с проверкой ключа сервера, не выполняет удалённые команды и закрывает туннель после запроса. Поддерживается и прямой HTTPS-адрес.

Для каждого устройства можно задать положительный лимит `max_loaded_bytes` для оценки памяти. Перед холодной загрузкой LM Studio Bridge вызывает `lms`, а для Unsloth — `/api/inference/estimate-memory`. Проверка настроенного лимита требует полной оценки. Сейчас Unsloth сообщает, что оценка недоступна, для форматов, которые не умеет рассчитывать, включая многие Transformers-модели. Bridge показывает такую оценку как неизвестную. Настроенный лимит блокирует загрузку при неизвестной оценке; без лимита Bridge дополнительно проверяет свежую RAM и видеопамять NVIDIA локально или через SSH, если доступна полная оценка кандидата.

По умолчанию `auto_unload_models` пуст, и Bridge не выгружает другие модели. Добавь в список точные ключи моделей, которые разрешено выгружать при подтверждённой нехватке памяти. Если движок явно вернёт ошибку нехватки памяти, а оценка неизвестна, Bridge также сможет выгрузить только разрешённые модели, проверить выгрузку и повторить загрузку. Целевая модель не выгружается, чтобы освободить место для самой себя. Результат загрузки перечисляет освобождённые экземпляры. `pair_smart_ask` ранжирует установленные модели и выбирает первую, прошедшую проверку памяти; явно указанную модель он не заменяет. В ответе будут причины отклонения других кандидатов. Это не точное предсказание будущего потребления: оставляй место для ОС и других программ. Запросы ждут до 30 секунд в очереди устройства; `/pair diagnose` показывает этапы очереди, загрузки и ответа. [Idle TTL и Auto-Evict LM Studio](https://lmstudio.ai/docs/developer/core/ttl-and-auto-evict) относятся к JIT загрузкам LM Studio; Bridge не меняет эти настройки.

Команда `pair_memory_plan(device, model, context_length)` показывает оценку без загрузки. Контекст существенно влияет на результат: на Alfred для Qwen3.8 27B получилось 19,24 GiB при 8192 токенах и 26,03 GiB при 65 536. Для загруженной модели Unsloth Bridge использует фактический контекст, если API его сообщает. `size_bytes` — размер весов на диске, а не полное потребление RAM/VRAM. `pair_devices` показывает свежие данные о доступной RAM, видеопамяти NVIDIA и месте на диске. [CLI LM Studio](https://lmstudio.ai/docs/cli/local-models/load), [инвентарь LM Studio](https://lmstudio.ai/docs/developer/rest/list), [API Unsloth Studio](https://github.com/unslothai/unsloth/tree/main/studio).

### Оцени память перед загрузкой

Для установленной, но выгруженной модели попроси Codex вызвать `pair_memory_plan` с точным устройством, ключом модели и нужным контекстом:

```json
{"device":"pc","model":"qwen/qwen3.8-27b","context_length":8192}
```

Ответ содержит оценку новой модели, оценки уже загруженных экземпляров с их фактическим контекстом, `required_with_headroom_bytes` и свежий замер ресурсов устройства. Холодная загрузка блокируется, если дополнительная потребность с запасом 10% превышает измеренную свободную RAM или видеопамять NVIDIA. Дополнительно можно задать `"max_loaded_bytes": 34359738368` (32 GiB) как отдельный лимит суммарной загрузки. Неизвестная оценка или доступная память показывается как `unknown`; заданный лимит по-прежнему блокирует загрузку при неизвестной оценке. Уже загруженная модель используется с прежним контекстом.

### Скачай новую модель отдельным действием

Скачивание не является частью запроса к модели. Для `pair_download_plan` укажи устройство, точный ID каталога LM Studio или URL репозитория Hugging Face и путь для проверки. Для GGUF-репозитория при необходимости задай `quantization`. Если источник — ID каталога либо метаданные недоступны или неоднозначны, укажи также проверенную оценку `estimated_size_bytes`. План выдаёт одноразовый ID на десять минут; `pair_download(plan_id, confirm_model)` требует повторить точный ID модели, а `pair_download_status` показывает ход задания. Само создание плана ничего не скачивает.

План может подтвердить размер **одного однозначного GGUF-файла** и ревизию репозитория; перед запуском он сверяет их повторно. Размер файла может отличаться от полного объёма задания LM Studio. Свободное место с запасом 10% проверяется только на локальном устройстве. Указанный путь нужен для проверки: LM Studio не подтверждает, что это его папка моделей. Для удалённого устройства сначала проверь фактическую папку и свободное место на нём. [API скачивания LM Studio](https://lmstudio.ai/docs/developer/rest/download).

Устройства добавляются явно. Обнаружение участников PAIR не даёт доступа к управлению их моделями. Управление Ollama, удаление весов, установка движков, скачивание моделей Unsloth и администрирование кластера PAIR пока не реализованы. Инструмент `pair_download` работает только с LM Studio; он требует отдельный одноразовый план и не вызывается обычным запросом к модели.

Если устройство требует авторизации, укажи в `api_key_env` имя переменной окружения с токеном и передай её MCP-процессу через `env_vars` в `.mcp.json`. Не сохраняй токены в Git и не вставляй их в запросы.

## Какие данные остаются локальными?

Мост работает на твоём компьютере и отправляет запросы **на настроенный тобой PAIR**. PAIR может передавать их подключённым серверам моделей. Автор плагина не получает запросы через этот плагин.

**Вся переписка с Codex при этом не обязательно локальная.** Ответы моделей возвращаются в Codex и обрабатываются согласно твоим настройкам Codex/OpenAI. PAIR и серверы моделей также могут сохранять собственные журналы. [Подробнее о данных](PRIVACY.md).

## Hermes Agent

PAIR Bridge включает OpenAI-совместимый шлюз для Hermes. Он показывает в каталоге как модели маршрутизатора PAIR, так и чат-модели из настроенных `devices` в `~/.pair-bridge.json`. Для адресации конкретного устройства используется ID `device/<id устройства>/<ключ модели>`; модели маршрутизатора сохраняют исходный ID PAIR. Для Unsloth-модели сначала вызови загрузку через PAIR Bridge: шлюз не загружает её в обход проверки памяти.

Чтобы автоматически запустить шлюз и зарегистрировать провайдера Hermes, из корня скачанного репозитория выполни одну команду:

```sh
python3 plugins/pair-bridge/scripts/install_hermes.py
```

Установщик сохраняет настройки через CLI Hermes, не меняет выбранную основную модель и запускает шлюз в фоне. Затем выбери PAIR Bridge через `hermes model` или `/model`. Нужны уже установленные `uv`, Hermes и настроенный файл конфигурации PAIR Bridge.

Ручной запуск шлюза (если не используешь установщик):

```sh
uv run --script ./plugins/pair-bridge/scripts/hermes_proxy.py
```

По умолчанию шлюз доступен только на `127.0.0.1:8765`. В `~/.hermes/config.yaml` добавь провайдера (оставив существующие записи):

```yaml
providers:
  pair-bridge:
    api: http://127.0.0.1:8765/v1
    api_key: local
    transport: openai_chat
model:
  provider: pair-bridge
  default: device/pc/qwen/qwen3-8b
  base_url: http://127.0.0.1:8765/v1
  api_mode: chat_completions
```

Замени `pc` и ключ модели на ID из `~/.pair-bridge.json` и ответа `GET http://127.0.0.1:8765/v1/models`. Для выбора другой модели используй `hermes model` или `/model`; список запрашивается у шлюза. Модели устройств адресуются напрямую, а обычные ID проходят через маршрутизатор PAIR.

Модели устройств должны быть установлены в настроенном движке, API должен быть доступен со шлюза. Модель Unsloth нужно сначала загрузить через PAIR Bridge, чтобы прошла проверка памяти. Шлюз принимает текстовые chat completion запросы и отдаёт совместимый с OpenAI поток SSE, если Hermes его запрашивает. По умолчанию это локальный интерфейс: для доступа по сети задай `HERMES_PAIR_HOST` и обязательно `HERMES_PAIR_API_KEY`; открой порт только в доверенной сети. `PAIR_BASE_URL` и `PAIR_API_KEY` задают адрес и ключ маршрутизатора так же, как для MCP-сервера.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Инструменты не появились | Открой новую задачу. Проверь, что плагин включён, а uv доступен в PATH приложения Codex. |
| Нет соединения с PAIR | Запусти PAIR и сверь адрес с файлом настроек. |
| Настроенное устройство недоступно | Проверь API настроенного движка, порт, прямое HTTPS- или SSH-подключение. |
| Модель есть в списке, но не отвечает | Открой сведения о запросе в PAIR и журнал сервера моделей. Список моделей не является проверкой их работоспособности. |
| Указанная модель не установлена | Запусти инвентаризацию через `/pair` и выбери точный ключ установленной модели; мост не скачивает отсутствующие веса. |
| Оценка памяти неизвестна или блокирует загрузку | Для LM Studio проверь `lms`; для Unsloth — поддерживает ли Studio оценку этого формата. Проверь контекст и лимит `max_loaded_bytes`. |
| План скачивания не проверил размер или путь | Укажи точный GGUF-репозиторий и квантование либо проверенную оценку размера. Сверь папку хранения LM Studio и свободное место на удалённом устройстве. |
| HTTP 400 или 500 | Проверь точное имя модели, её загрузку, доступную память и ошибки сервера. |
| Другой запрос уже выполняется | Дождись завершения текущего вызова через мост. |
| Истекло время ожидания | Перед повтором проверь PAIR: предыдущая генерация могла продолжиться. |
| Нет итогового текста | Модель могла потратить лимит вывода на рассуждения. Проверь результат перед увеличением лимита. |

## Slash-команда и MCP-инструменты

`/pair` включает навык, который объясняет Codex порядок безопасной работы с моделями. Имена ниже — MCP-инструменты этого навыка, а не команды терминала.

Без `device` инструменты `pair_list` и `pair_ask` работают через маршрутизатор PAIR. С параметром `device` они обращаются напрямую к настроенному движку. Для прямого запроса должен быть загружен ровно один экземпляр выбранного ключа модели.

**`pair_ask`** — принимает обязательные `model` (точное имя из `pair_list`) и `prompt` (вопрос). Необязательный `max_tokens` по умолчанию равен `2048`.

Пример параметров `pair_ask` — замени имя модели:

```json
{
  "model": "<точное имя из pair_list>",
  "prompt": "Проверь пограничные случаи этой функции: ...",
  "max_tokens": 2048
}
```

## Справочник инструментов

| Инструмент | Что принимает | Что возвращает |
| --- | --- | --- |
| `pair_devices` | Без параметров. | Доступность, установленные и загруженные модели, время проверки, свободные RAM, видеопамять NVIDIA и место на диске. |
| `pair_list` | Необязательный `device`. | Каталог маршрутизатора PAIR или нативный список одного устройства. Если каталог пуст, возвращает установленные модели доступных настроенных устройств с явными устройством и состоянием загрузки. |
| `pair_load` | `device`, `model`, необязательный `context_length`. | Использованный или новый экземпляр и его точный идентификатор. |
| `pair_memory_plan` | `device`, установленная `model`, необязательный `context_length`. | Оценка памяти без загрузки, включая работающие экземпляры при их фактическом контексте. |
| `pair_unload` | `device`, `instance_id`. | Подтверждение, что один точный экземпляр больше не наблюдается. |
| `pair_ask` | `model`, `prompt`, необязательные `device`, `max_tokens`. | Ответ, модель, статус завершения, время и сведения о токенах, если доступны. |
| `pair_smart_ask` | `prompt`; необязательные `model`, `device`, `task_hint` (`general`, `code`, `fast`, `long_context`, `analysis`), `context_length`, `max_tokens`, `unload_after`. | Выбирает установленную модель по живому инвентарю, загружает при необходимости, задаёт один вопрос и сообщает результат очистки. |
| `pair_benchmark` / `pair_benchmark_results` | Точная загруженная модель и устройство, профиль, 3–12 проверенных примеров с `prompt` и буквальным `expected_contains`. | Измеряет число успешных проверок и задержку. Недавние результаты влияют на выбор модели; сохраняются только метрики. |
| `pair_job_start` / `pair_job_status` / `pair_job_cancel` / `pair_job_recover` | Для запуска — устройство, модель и запрос; затем ID задания. | Фоновый запрос с этапами загрузки, обработки, ответа и очистки, частичным текстом, отменой и безопасным восстановлением по журналу. |
| `pair_compare` | Вопрос и две точные пары «устройство/модель». | Два последовательных ответа, общие и спорные замечания; Codex проверяет их по исходному коду. |
| `pair_diagnose` | Нет. | Состояние PAIR и устройств, недавние этапы запросов, длительности и безопасные причины ошибок без текста запросов и токенов. `request_journal_status` показывает `ok`, `not_created`, `permission_denied` или `unavailable`; ошибка доступа к журналу не прерывает диагностику. |
| `pair_download_plan` / `pair_download` / `pair_download_status` | Точная модель и путь; оценка размера при неизвестных метаданных; одноразовый ID плана, повторное `confirm_model`; ID задания. | Для однозначного GGUF-файла Hugging Face план проверяет размер и ревизию. Место проверяется с запасом 10%, когда настроенный `models_path` совпадает с местом загрузки. Иначе фактический путь хранения остаётся непроверенным. Для ID каталога нужна введённая оценка. Фактический размер задания LM Studio сообщает после запуска. |
| `pair_decide` / `pair_score` | Состояние, варианты Choice или упорядоченные уровни Score, `allow_external=true`. | Необязательная типизированная оценка облачной модели TypeSafe AI Jev; нужен `TYPESAFE_API_KEY`. |

Умный путь требует хотя бы одно настроенное и доступное устройство. Он сохраняет уже загруженные экземпляры. После успешного ответа экземпляр, загруженный этим вызовом, по умолчанию выгружается; после ошибки или тайм-аута остаётся для проверки. Мост не видит работу других приложений с движком: если модель общая, задай `unload_after=false`.

Для Oh My Pi добавлены собственные `/pair` и навык; см. [инструкцию подключения OMP](docs/OMP.md). Jev — отдельный внешний сервис решений, а не локальная чат-модель; данные отправляются ему только при явном `allow_external=true`.

<details>
<summary><strong>Лимиты и поведение запросов</strong></summary>

- Перед обращением к модели список обновляется; нужно точное имя.
- Предполагаемые embedding- и draft-модели отсекаются для чат-запросов. Тип определяется по имени.
- Загрузка, выгрузка и генерация ставятся в очередь отдельно для каждого настроенного устройства между процессами моста одного пользователя. Запросы к маршрутизатору используют отдельную блокировку, поскольку конечный узел неизвестен. Другие приложения этим ограничением не охвачены.
- Нет автоматических повторов, подмены модели или скачивания весов при запросе. Сервер может загрузить уже установленную модель и занять GPU/RAM.
- Лимит вывода по умолчанию — 2 048 токенов; диапазон — 32–8 192. Входной текст — до 48 000 символов. Ограничения контекста самой модели также действуют.
- Ожидание ответа — до 180 секунд. Отмена или тайм-аут не гарантируют остановку генерации на сервере.
- Пустой итоговый ответ считается ошибкой. Ответ, остановленный лимитом токенов, помечается как обрезанный.
- Выгрузка затрагивает точный экземпляр настроенного движка и может помешать другому приложению, которое его использует. Навык отслеживает загрузки текущей задачи и избегает выгрузки чужих экземпляров.
- Мост не меняет постоянные настройки движков и не исправляет каталоги. Явная загрузка может задать размер контекста.

</details>

## Переход с `codex-pair-bridge`

Новое имя marketplace и плагина — `pair-bridge`. Старый файл `~/.codex-pair-bridge.json` продолжает работать; новый `~/.pair-bridge.json` имеет приоритет. Каталог локального журнала сохраняет старое имя ради истории. Для установленной старой версии:

```sh
codex plugin remove codex-pair-bridge@codex-pair-bridge
codex plugin marketplace remove codex-pair-bridge
codex plugin marketplace add GermanMik/pair-bridge
codex plugin add pair-bridge@pair-bridge
```

## Обновление плагина

Попроси Codex: «`/pair обнови плагин на этом компьютере`». Навык проверит установленный плагин и источник каталога, обновит его штатными командами Codex, затем покажет установленную версию. Для Git-каталога используются команды:

```sh
codex plugin marketplace upgrade pair-bridge
codex plugin add pair-bridge@pair-bridge
```

Обновляется только этот компьютер с Codex; мост не подключается для обновления к настроенным устройствам LM Studio. Для локального источника обнови исходный каталог по его обычному процессу. После обновления открой новую задачу, чтобы Codex увидел навык `/pair` и текущие MCP-инструменты. Версия 0.7.0 добавляет установку Hermes одной командой и OpenAI-совместимый шлюз PAIR с ID моделей по устройствам. Версия 0.6.2 показывает установленные модели настроенных устройств, даже когда каталог маршрутизатора PAIR пуст. Версия 0.6.1 исправила замер свободной памяти при локальном запуске Bridge на Windows. Версия 0.6.0 добавила измерение ресурсов, выбор модели по локальным бенчмаркам и фоновые запросы с отменой и восстановлением.

## Разработчикам

Инструкции по окружению, тестам и первому вкладу собраны в [руководстве участника](CONTRIBUTING.ru.md).

```sh
cd plugins/pair-bridge
uv run --locked --script ./scripts/server.py --self-test
```

Автоматические тесты проверяют MCP, параметры, настройки, планирование SSH-туннеля, инвентаризацию, загрузку и выгрузку, ошибки, тайм-ауты, блокировку операций и разбор ответов. CI запускается на **macOS, Windows и Linux**. Ранее маршрутизируемые и прямые запросы проверялись на macOS и удалённом Windows-узле; новые сценарии требуют отдельной проверки на реальных устройствах.

Зависимости зафиксированы в `scripts/server.py.lock`. Для обновления используй `uv lock --script scripts/server.py`, затем запусти тесты.
