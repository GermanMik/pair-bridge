## Перед началом

Сначала проверьте существующие issues и pull requests. Для крупного изменения создайте issue и согласуйте ожидаемое поведение до начала реализации. Небольшие исправления и изменения документации можно сразу отправлять в pull request.

PAIR Bridge — MCP-сервер с приоритетом локальной работы для совместимых клиентов. Описывайте поддержку движков, клиентов и способов удалённого управления только тогда, когда она реализована и проверена.

## Подготовка окружения

Понадобятся Python 3.11–3.14 и установленный [uv](https://docs.astral.sh/uv/getting-started/installation/).

```sh
git clone https://github.com/GermanMik/pair-bridge.git
cd pair-bridge/plugins/pair-bridge
uv --version
uv run --locked --script ./scripts/server.py --self-test
```

Self-test — та же проверка, которую выполняет CI. Он проверяет MCP-протокол и тесты моста без запущенного маршрутизатора PAIR или моделей. CI запускается на Linux, macOS и Windows. Для изменений реального взаимодействия с PAIR или LM Studio дополнительно нужны проверки на соответствующем устройстве.

## Где вносить изменения

Код плагина и его тесты находятся в `plugins/pair-bridge/scripts/`:

- `server.py` — MCP-инструменты, маршрутизация, проверка аргументов и обработка запросов.
- `management.py` — настроенные устройства LM Studio и управление экземплярами моделей.
- `telemetry.py`, `benchmarks.py`, `jobs.py`, `diagnostics.py` — замеры ресурсов, выбор по измерениям, фоновые задания и безопасные журналы запросов.
- `download_review.py` — отдельный план загрузки весов и связанные ограничения.
- `jev.py` — интеграция с Jev.
- `test_*.py` — тесты функций и протокола.

Инструкции для пользователей обновляйте в `README.md` и `README.ru.md`, подробности работы — в `docs/`.

## Безопасные и понятные изменения

- Один pull request — одна понятная задача; опишите изменение с точки зрения пользователя.
- При изменении поведения добавьте или обновите регрессионный тест, включая проверку ошибки, если это уместно.
- Сохраняйте явный контроль пользователя: запрос не должен незаметно скачивать веса или заменять явно указанную модель. Автоматический выбор обязан пройти проверку памяти. Чужой экземпляр можно выгрузить только при нехватке памяти и если его точный ключ модели указан в `auto_unload_models` этого устройства.
- Не добавляйте в Git ключи, адреса приватных сетей, реальные запросы к моделям, личные журналы или настройки конкретного компьютера. Используйте синтетические примеры и очищайте диагностику.
- Если меняются зависимости, намеренно обновите метаданные inline-скрипта и lock-файл: CI использует `uv run --locked`.
- При изменении настройки, безопасности или видимых пользователю инструментов обновите документацию на русском и английском.

## Проверка перед pull request

- [ ] Объём изменения понятен и объяснена причина.
- [ ] Тесты проверяют новое поведение и подходящие сценарии ошибок.
- [ ] `uv run --locked --script ./scripts/server.py --self-test` проходит.
- [ ] При необходимости обновлена документация на обоих языках.
- [ ] В изменениях нет ключей, личных запросов и данных конкретной машины.
- [ ] Для реальных устройств указаны проверенные платформы и версии; непроверенные варианты отмечены.

Не нужно утверждать, что проверены все сочетания устройств. Укажите только то, что действительно тестировали.

## Issues и первые задачи

Метка [good first issue](https://github.com/GermanMik/pair-bridge/labels/good%20first%20issue) предназначена для небольших самостоятельных задач с ясным результатом, которым не предшествует решение по архитектуре. Если таких открытых задач нет, предложите небольшую задачу через форму улучшения или попросите сопровождающих разделить крупную задачу. В сообщении об ошибке укажите клиент, ОС, версии PAIR/LM Studio, нужные сведения о модели и устройстве, шаги воспроизведения, ожидаемый и фактический результат, очищенный текст ошибки. Не прикладывайте токены или личные запросы.

PAIR Bridge — независимый проект сообщества, не связанный с NVIDIA или OpenAI и не одобренный ими.
