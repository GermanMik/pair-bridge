# ProofLoop 04: resource management

Acceptance: per-device calls queue for at most 30 seconds; cold loads preflight the candidate at its planned context, loaded instances at their actual contexts and fresh available RAM/VRAM. Configured `max_loaded_bytes` blocks a cold load when estimates plus 10% headroom exceed the budget. `auto_unload_models` is an exact per-device allowlist: only listed model instances may be unloaded after an insufficient-memory preflight, one at a time, with state verification and a fresh preflight after each unload. Without that setting, other instances are preserved. Automatic model selection chooses the highest-ranked candidate that passes preflight; explicit model requests are never substituted. Queue/load/inference stages are visible in the local journal while running; load results report LM Studio load time, allowlisted instances released, and any other instances observed to disappear during loading. Automatic cleanup after inference still targets only the exact instance ID returned by that request's load call.

Evidence: existing tests cover device locks, loaded-context estimates, configured limits, capacity telemetry, exact-instance unloads, smart ask cleanup and timeout retention. New tests cover skipping a ranked candidate that fails memory preflight and unloading only an allowlisted exact instance with a fresh preflight. A real cold-load/unload was not performed.

Update: `pair_memory_plan` and all cold-load paths use the read-only LM Studio CLI estimate through the target device tunnel. The current implementation rechecks fresh RAM/VRAM before loading. A live Alfred check estimated the installed Qwen3.8 27B at 8,192 context while accounting for loaded Ornith at its actual 65,536 context and a loaded embedding model. The CLI prints estimates to stderr, which the parser accepts. Download-plan tests cover unambiguous Hugging Face file metadata, insufficient local space and revision changes before start; the public metadata lookup did not complete from this environment, so its live success remains unverified.

Limits: native synchronous LM Studio load returns `load_time_seconds` after completion, not a percentage stream. The estimate is not measured free RAM/VRAM; the configured budget must leave OS headroom. When no budget is configured, an unavailable estimate is reported but does not block loading. LM Studio's Idle TTL and Auto-Evict are JIT server settings; Bridge neither changes them nor assumes they protect explicit loads. See https://lmstudio.ai/docs/developer/core/ttl-and-auto-evict and https://lmstudio.ai/docs/developer/rest/load.
