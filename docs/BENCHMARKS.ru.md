# Бенчмарки моделей через PAIR

Данные доступны любому клиенту подключённого MCP-сервера PAIR Bridge. Запуск, чтение истории и сравнение используют одно локальное хранилище. Новые HTTP-маршруты в NVIDIA Personal AI Router не добавляются.

| Набор | Заданий | EN / RU | Назначение |
| --- | ---: | --- | --- |
| `smoke` | 6 | 3 / 3 | Арифметика, простые инструкции, строгий JSON |
| `short` | 20 | 10 / 10 | Быстрое сравнение по всем пяти категориям |
| `full` | 100 | 50 / 50 | По десять параметризованных вариантов на категорию и язык |

Наборы вложены: первые 6 заданий `short` составляют `smoke`, первые 20 `full` — `short`. Категории: арифметика, логика, JSON, понимание Python-кода, извлечение значения из синтетического контекста примерно на 10 тысяч символов. Сгенерированный код не выполняется. Это ограниченный тест, который не доказывает общую интеллектуальность, качество генерации программ, максимальную длину контекста, vision/embedding или работу с инструментами.

## Инструменты для систем-потребителей

- `pair_benchmark_suites()` — описание наборов, версия, SHA-256 fingerprint, распределение категорий и языков.
- `pair_benchmark_run(device, model, suite="short", repeats=3, max_tokens=256)` — фоновый запуск; возвращает `job_id`, `run_id` и число измеряемых ответов. Допустимы 1–5 повторов и минимум 32 выходных токена. Фиксированного максимума Bridge нет: учитываются свежие явные лимиты модели и фактический загруженный контекст, без обрезания бюджета. Если лимиты неизвестны, их проверяет движок с учётом входа и reasoning. Для reasoning-моделей указывайте больший бюджет явно.
- `pair_job_status(job_id)` / `pair_job_cancel(job_id)` — состояние и отмена.
- `pair_benchmark_results(run_id=...)` — сохранённый результат; также фильтры `device`, `model`, `suite` и страницы `limit` (1–200), `offset`.
- `pair_benchmark_compare(run_ids=[...])` — сравнение 1–20 завершённых прогонов: структурированные строки и `table_markdown`.

Перед запуском требуется ровно один уже загруженный экземпляр модели с известным контекстом. Используйте существующие инструменты PAIR для явной загрузки. Бенчмарк не загружает/выгружает модели, не меняет настройки, не подменяет модель и не повторяет неудачный запрос.

Один прогрев исключается из измерений; затем выполняются повторы фиксированного набора при temperature=0. Устройство заблокировано на весь прогон существующей очередью. Один запрос ограничен настраиваемым таймаутом (по умолчанию 180 секунд), ожидание блокировки — 30 секундами. При технической ошибке прогон останавливается: следующий запрос не отправляется, частичные данные сохраняются. Отмена закрывает поток Bridge, но не подтверждает остановку вычислений движка.

## Качество, скорость и ошибки

Результат содержит версию/fingerprint набора, время, модель, устройство, движок, точный экземпляр, фактический контекст и параметры генерации. Версия runtime, оборудование и квантизация пока возвращаются как `null` с объяснением в `unknown_reasons`; названия моделей не используются для догадок.

- `quality`: успешные проверки / все измеряемые ответы, `pass_rate` от 0 до 1; отдельные `by_category` и `by_language` (`ru`, `en`). Технический сбой уменьшает общий результат. Если ответов нет, оценка `null`.
- `speed`: медиана и p95 полного времени, время до первого непустого фрагмента финального ответа, токены/сек. Каждая метрика имеет `value`, `samples`, `reason`. Токены/сек — число выходных токенов, сообщённое движком, делённое на полное время; включает обработку входа и может включать reasoning. Это не чистая скорость декодирования. Без usage значение `null`, оценка токенов по тексту не применяется. Технические сбои исключены из расчёта скорости.
- `errors`: количество и виды технических/форматных ошибок. Неверное содержание — `mismatch`, отдельно в `incorrect_answers`; неверный JSON/тип, обрезанный ответ — `format_error`.
- `cases`: идентификатор задания, категория, язык, повтор и метрики. Промпты, ожидаемые ответы, reasoning и сгенерированный текст не сохраняются.

Сравнение требует одинаковых наборов, версий/fingerprint, контекста, выходного бюджета, повторов и прогрева. Устройства и модели могут различаться; условия видны в каждой строке. Частичные, отменённые и неудачные прогоны сравнивать нельзя. Пустая история возвращает `status=not_measured`, а отсутствующая метрика отображается в таблице как `—`.

## История и автоматический выбор

`pair_benchmark_run` принимает `request_timeout_seconds` (30–1200, по умолчанию 180) и `enable_thinking` (по умолчанию null — настройки движка). Явный режим thinking доступен только при объявленной поддержке поля Unsloth; иначе прогон завершается до прогрева. Настройки применяются только к запросу. Оба поля сохраняются и определяют совместимость результатов. Старые записи означают таймаут 180 и режим движка. Завершение прогона без thinking не подтверждает прежний прогон в штатном режиме.

Повреждённые записи пропускаются: `invalid_records` показывает их число на текущей странице, `history_warning=invalid_records_skipped` сообщает об ошибке. `total` и смещение страниц учитывают все сохранённые записи. Корректные результаты остаются доступны для маршрутизации.

История находится в `benchmark-runs.sqlite3` локального пользовательского cache PAIR Bridge. `run_id` позволяет читать результат после перезапуска. Незавершённые записи другого процесса/сессии имеют статус `interrupted_or_other_process`. Разные компьютеры используют отдельные хранилища; для общей истории потребители должны обращаться к одному Bridge MCP-сервису.

В маршрутизации участвуют только завершённые `short`/`full` с текущим fingerprint, не старше 30 дней. Выбирается один совместимый набор условий по самому новому подходящему прогону; разные условия не смешиваются. `smoke` служит проверкой работоспособности. Старый `pair_benchmark` сохранён; `pair_benchmark_results(profile, context_length)` продолжает возвращать сводку для маршрутизации. Для истории новых наборов аргумент `profile` нужно опустить.

Изменения исходников не обновляют установленный плагин: новые инструменты появятся после обычного обновления плагина и перезапуска его MCP-сервера. Изменение заданий/валидаторов требует новой версии набора.
